# 账号登录与跨设备历史同步设计（已确认）

日期：2026-11-20

状态：用户已确认本方案并授权施工。实施结果与验证边界见《账号功能施工验收说明》。

## 1. 本次范围

电脑、手机和平板通过浏览器访问同一个网站，登录同一账号后读取和编辑同一套私人讲义历史。本次不对接 DeepSeek Harness 插件，不开发原生客户端，也不接入微信、QQ 等第三方登录。

保留游客使用：未登录时继续使用本机历史；登录后提供“账号历史”及按需导入本机讲义的入口。账号历史默认私密，发布到社区仍是独立的主动操作。

## 2. 登录方式建议

推荐首版采用邮箱和密码：提供注册、邮箱验证、登录、退出和忘记密码。首次完成邮箱验证后开放账号云端存储，验证码及重置链接应短时有效、单次使用。

邮箱验证码登录也可实现，但每次登录都依赖邮件送达；第三方登录则需要额外应用注册和回调配置。因此先采用邮箱密码，后续可扩展其他入口。

生产上线需配置邮件发送服务和网站 HTTPS 域名。开发测试使用模拟邮件发送器，不发送真实邮件、不把验证或重置凭据写到生产日志。邮件服务未配置时页面和游客功能仍可用，注册及密码找回提示暂不可用。

密码采用成熟库提供的 Argon2id 哈希；会话使用服务端可撤销的随机令牌，通过 HttpOnly、Secure、SameSite=Lax Cookie 传递，不存入浏览器 localStorage。登录后轮换会话，重置密码后撤销旧会话；允许多个设备同时登录。

## 3. 历史保存和恢复

- 游客：现有本机讲义继续留在浏览器，登录不等于同意上传这些内容。
- 已登录：新建或编辑的账号讲义自动保存至服务器，页面明确显示“保存中”“已同步”或“保存失败”。
- 首次登录：列出可导入的本机讲义，用户选择后上传；不删除本机原件。重复导入相同本机记录不产生重复讲义。
- 更换设备：登录后展示账号历史；打开时取得服务器最新版本。
- 导入范围：讲义标题、完整模块内容、习题答案及编辑版本；不包含原始上传文件、生成用参考全文、匿名分享管理令牌及其他设备隐私数据。
- 导出：保留 DOCX 和打印功能，另提供讲义 JSON 备份用于恢复编辑。

账号讲义按用户隔离。服务端从会话取得所有者身份；不得信任客户端传来的账号 id。读取、更新、导出、版本恢复和删除都检查所有权。

## 4. 同步与并发编辑

首版采用保存时同步，历史页面打开或重新获得焦点时刷新；不是实时协同编辑。

每份讲义带服务器版本号。客户端提交保存时携带读取时的版本号：一致才更新；不一致则返回冲突，保留服务器版本和当前设备的未同步版本。界面允许用户查看最新版本、将本机内容另存为副本，或基于最新版本继续编辑；不得静默覆盖。

同一页面串行保存并合并待保存改动，防止快速输入导致旧请求覆盖新请求。断网或登录过期时保留当前编辑内容，提示恢复连接或重新登录；成功后再提交，不能显示虚假的“已同步”。

未同步内容可暂存于按账号隔离的浏览器恢复区。退出前处理未同步内容：等待保存、下载备份后退出，或明确放弃。正常退出清除该账号的本地缓存及页面数据；切换账号时停止旧账号待保存任务，禁止把上一账号内容写入新账号。

## 5. 版本与删除

保存时为讲义记录修订版本，首版每份最多保留最近 20 个成功保存版本。恢复旧版会生成一个新版本，并接受同样的并发检查。

账号删除讲义后进入回收站，保留 30 天可恢复；同步删除标记，其他设备的旧保存请求不能复活已删除讲义。用户可明确选择永久删除；到期清理通过服务器维护任务执行。

建议初始容量为每账号 200 份讲义、每份规格最多 1 MiB、每账号包含版本和回收站共 100 MiB。上限在服务器强制执行，并在界面显示；容量不足时允许导出或清理，不丢弃正在编辑的内容。

## 6. 与社区的关系

私人账号历史和社区公开记录分开。发布时复制一份经用户确认的讲义快照；之后修改私人讲义不会自动改变公开内容，删除私人讲义也不会自动撤回分享。

登录用户的新分享关联账号，可在“我的分享”管理。已有匿名分享仍保留原管理链接；若要绑定到账号，必须验证原管理令牌，不能按展示名称或讲义标题认领。被管理员隐藏的内容不能由发布者通过更新直接恢复公开。

## 7. 服务端与数据结构

复用现有 Node 服务，为 SQLite 增加顺序执行的版本化迁移：

| 数据表 | 内容 |
| --- | --- |
| users | 标准化邮箱、密码哈希、显示名称、邮箱验证状态 |
| sessions | 会话令牌摘要、所属用户、过期时间、撤销状态 |
| auth_tokens | 验证/重置令牌摘要、用途、过期和使用状态 |
| private_handouts | 所有者、标题、当前规格、版本号、更新时间、删除标记 |
| handout_revisions | 所有者、讲义 id、版本快照和时间 |
| history_imports | 用户与本机来源记录的唯一映射，防止重复导入 |

社区记录新增可为空的所有者字段，兼容原匿名分享。数据库变更使用事务，迁移前备份；初版适用于单个 Node 服务实例和持久化磁盘，不把 SQLite 放在会被重置的临时文件系统。

建议接口分为 `/api/auth/*`（注册、验证、登录、会话、退出、密码重置）和 `/api/account/handouts/*`（历史列表、读取、保存、导入、版本、回收站及恢复）。公开社区接口保持独立。

所有状态修改接口校验请求来源和 CSRF；注册、登录、验证及重置请求限频，避免错误提示泄露邮箱是否存在。认证响应禁止缓存，日志不记录密码、Cookie、令牌或私人讲义正文。

## 8. 界面调整

- 顶部新增“登录 / 注册”，登录后展示账号菜单与退出入口。
- 历史页区分“账号历史”“本机历史”“回收站”。
- 编辑页显示当前保存位置、同步状态、冲突及版本恢复入口。
- 本机导入提供逐份勾选、重复记录处理与导入结果。
- 手机、平板和电脑使用相同账号流程，表单与弹窗适配窄屏。

## 9. 施工顺序与验收

1. 先修正现有历史保存流程中的错误反馈、页面切换保存和缓存隔离，再添加数据库迁移。
2. 实现注册验证、登录会话、退出和密码找回，测试过期、限频及令牌重复使用。
3. 实现受所有权保护的私人历史、版本管理和回收站，验证不同账号不能读取或修改彼此数据。
4. 接入本机导入与同步界面，验证重复导入、断网恢复、快速编辑和双设备版本冲突。
5. 连接账号分享管理，保留匿名分享凭据兼容性，验证私人改动不自动公开。
6. 用两个独立浏览器会话验证“电脑保存—手机恢复—两端编辑冲突—退出换账号”，检查三个屏幕尺寸；运行原插件与现有网站回归检查。

## 10. 上线条件与当前边界

跨设备互通需要所有设备访问同一个已部署的网站。当前 localhost 预览只能用于本机验证；把源码上传 GitHub 不会自动变成公网账号服务。

实现和本地测试可先完成；公开上线还需要 HTTPS 域名、持久化数据库、邮件发送配置和备份策略。开发阶段不向用户索取或在聊天中保存真实密码、邮箱服务密钥。

本方案已获确认；账号、历史同步与分享归属功能已进入实施及验收。
